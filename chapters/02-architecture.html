פרק 2: איך Geant4 בנוי

מה Geant4 יוצר הכי הרבה?

בפרק 1 ראינו שריצת ה-Be של ldns העבירה \(3\times10^{6}\) פרוטונים דרך ממיר בעובי 2 mm. בפרק הזה נפתח את Geant4 מבפנים: איך הוא מארגן את העבודה, באיזה סדר הוא עובר על החלקיקים, ואיפה הקוד של ldns נכנס לתמונה.

Geant4 בונה את הסימולציה מארבעה סוגי אובייקטים, זה בתוך זה: ריצה (run), אירוע (event), מסלול (track) וצעד (step). את כולם פגשנו בפרק 1. השאלה הראשונה פשוטה: מאיזה סוג נוצרו הכי הרבה עותקים בריצה הזאת?

הצעדים מנצחים בפער של סדר גודל ויותר. כל פרוטון הוא אירוע אחד ומסלול אחד, אבל הוא עושה כמה צעדים לפחות: אחד מהמקור עד הממיר דרך הוואקום, ועוד כמה בזמן שהוא מאט. כמה בדיוק תלוי ברשימת הפיזיקה ובאנרגיה; בצעצוע שלנו 40, וזה המספר שנשתמש בו גם בתרגילים. משניים, כמו הנייטרון, נוצרים רק באירועים מעטים: בריצה האמיתית נייטרון אחד לכל כ-2200 פרוטונים.

לכן מה שקורה בכל צעד, כלומר הקוד שרץ בפעולת הצעד, הוא הקוד החם ביותר באפליקציה. בצעצוע שלנו, כל שורה מיותרת שם רצה \(1.2\times10^{8}\) פעמים בריצה אחת.

2

ארבע קופסאות, זו בתוך זו

נחזור לאירוע הסכמטי של פרק 1: פרוטון של 6.3 MeV נכנס ל-Be, מאט, ובצעד האחרון שלו תגובה לא-אלסטית יוצרת נייטרון, גמא וגרעין. הגמא עושה פיזור קומפטון ומעיף אלקטרון. הפעם נסתכל גם על מה ש-Geant4 מחזיק בזיכרון בכל רגע.

מתחת לציור יש ארבע קופסאות, כמו ב-Geant4: G4Run מכיל אירועים, G4Event מכיל מסלולים, וכל G4Track מתקדם בצעדים, G4Step. התגובה של הפרוטון, מסלול 1, יוצרת את הנייטרון, הגמא והגרעין, והם מקבלים את המספרים 2, 3 ו-4.

זה אוצר המילים של כל הפרק. החלקיק שהמקור יורה הוא החלקיק הראשוני (primary), וכל מה שנוצר אחריו הוא משני (secondary). לכל מסלול יש מספר (track ID), מספר ההורה הישיר שלו (parent ID, ואפס לראשוני), התהליך שיצר אותו (creator process), ומשקל סטטיסטי (weight) שעובר בירושה מההורה.

הצעד הוא הקטע בין נקודת ההתחלה (PreStepPoint) לנקודת הסיום (PostStepPoint). האנרגיה הקינטית בנקודת ההתחלה היא האנרגיה שהחלקיק הביא לצעד, ובנקודת הסיום רשום התהליך שקבע את אורך הצעד. ldns משתמש בשניהם: לכל נייטרון שנולד הוא רושם את האנרגיה של ההורה בתחילת הצעד שבו קרתה התגובה, ואת שם התהליך.

זה כמו ספרייה. ריצה היא מדף, אירוע הוא ספר, מסלול הוא פרק, וצעד הוא משפט. כל ספר מתחיל בפרק אחד, הפרוטון, ופרקים חדשים נכתבים תוך כדי, עם הפניה לפרק שממנו יצאו.

3

איפה הקוד שלנו נכנס

Geant4 הוא ספרייה, לא תוכנה מוכנה. כדי שירוץ, האפליקציה חייבת לתת לו שלושה דברים: גיאומטריה, רשימת פיזיקה (physics list) ומקור של חלקיקים ראשוניים. אלה השורות מ-ldns.cc, הפונקציה main, שבונות את מנהל הריצה, הגיאומטריה ורשימת הפיזיקה:

  auto runManager = G4RunManagerFactory::CreateRunManager(G4RunManagerType::Default);
  runManager->SetNumberOfThreads(std::max(1, nThreads));

  auto det = new DetectorConstruction();
  runManager->SetUserInitialization(det);

  G4PhysListFactory factory;
  if (!factory.IsReferencePhysList(physName)) {
    G4cerr << "Unknown physics list: " << physName << G4endl;
    return 1;
  }
  G4VModularPhysicsList* phys = factory.GetReferencePhysList(physName);

רשימת הפיזיקה לא נכתבת ביד: G4PhysListFactory מחזיר רשימה מוכנה לפי השם, כאן QGSP_BIC_AllHP_EMZ (פרק 4). ובהמשך אותו קובץ, מנהל הריצה מקבל את רשימת הפיזיקה ואת אתחול הפעולות, נבנים ה-messengers שמגדירים את פקודות המאקרו, ובסוף מגיע מנהל הפקודות:

  runManager->SetUserInitialization(phys);
  runManager->SetUserInitialization(new ActionInitialization(det, physName));

  // master-only messengers for the shared source / output configuration
  auto srcMessenger = new SourceMessenger(SourceSpectrum::Instance());
  auto outMessenger = new OutputMessenger();
  auto xsDump = new XSDump();

  auto vis = new G4VisExecutive("Quiet");
  vis->Initialize();

  auto UImanager = G4UImanager::GetUIpointer();

מעבר לחובה, אפשר לתת ל-Geant4 פעולות משתמש (user actions): מחלקות שהוא קורא להן ברגעים קבועים של הריצה. ldns רושם ארבע, בקובץ src/ActionInitialization.cc:

void ActionInitialization::Build() const
{
  SetUserAction(new PrimaryGeneratorAction);
  auto run = new RunAction(fDet, fPhysList);
  SetUserAction(run);
  auto evt = new EventAction(run);
  SetUserAction(evt);
  SetUserAction(new SteppingAction(fDet, evt));
}
  • חובה: DetectorConstruction (הגיאומטריה), רשימת הפיזיקה, PrimaryGeneratorAction (המקור, הפונקציה GeneratePrimaries), ו-ActionInitialization שרושם את הפעולות.
  • רשות: פעולת ריצה, פעולת אירוע, פעולת מסלול (tracking), פעולת צעד (stepping) ופעולת מחסנית (stacking). ל-ldns יש שלוש מהן: ריצה, אירוע וצעד.

למטה ריצה סכמטית של שני אירועים. כל שורה היא קריאה של Geant4, והיא נדלקת ברגע שהיא קורית. ldns אוסף לכל אירוע את סכום המשקלים של הנייטרונים שיצאו מהממיר, במשתנה fLeak, כדי לחשב אחר כך את השגיאה מהפיזור בין האירועים (פרק 1).

זה הקוד של src/EventAction.cc: האיפוס בתחילת כל אירוע, ובסופו העברת הסכומים לפעולת הריצה, שמחברת אותם וגם את הריבועים שלהם:

void EventAction::BeginOfEventAction(const G4Event*)
{
  fSrcW = fLeak = fLeakFwd = fConv = 0.;
  fModAll = fModBand = fModBandFwd = fModBandFace = 0.;
  fConvLayer.fill(0.);
  fLeakedTracks.clear();
}

void EventAction::EndOfEventAction(const G4Event* event)
{
  if (auto v = event->GetPrimaryVertex()) fSrcW = v->GetWeight();
  fRun->AddEvent(fSrcW, fLeak, fLeakFwd, fConv, fConvLayer);

הסדר קבוע: BeginOfRunAction פעם בריצה; לכל אירוע GeneratePrimaries ואחריה BeginOfEventAction; לכל מסלול PreUserTrackingAction, קריאה של UserSteppingAction לכל צעד, ו-PostUserTrackingAction; בסוף האירוע EndOfEventAction, ובסוף הריצה EndOfRunAction. כל מה שהאפליקציה סופרת נכנס באחד הרגעים האלה.

Geant4 הוא כמו מנצח שמנהל את התזמורת, והקוד שלנו הוא נגנים שמחכים לתור. אנחנו לא קובעים מתי לנגן; אנחנו רק כותבים מה לנגן כשהמנצח מצביע עלינו.

4

המחסנית: האחרון שנכנס יוצא ראשון

Geant4 מעביר מסלול אחד בכל פעם, עד הסוף. חלקיק משני שנוצר בדרך לא מתחיל לזוז מיד: הוא מחכה במחסנית (stack). כשהמסלול הנוכחי נגמר, המשניים שלו מקבלים מספרים לפי סדר היצירה ונכנסים למחסנית, ו-Geant4 שולף ממנה את המסלול הבא.

בציור, הפרוטון (מסלול 1) כבר נגמר. במחסנית מחכים, מלמטה למעלה, הנייטרון (2), הגמא (3) והגרעין (4).

זו מחסנית במובן של מדעי המחשב: האחרון שנכנס יוצא ראשון (LIFO, last in first out). לכן הגמא מועבר לפני הנייטרון, והאלקטרון שהגמא יצר קופץ לראש התור ומועבר מיד אחריו. הסדר המלא באירוע הוא 1, 4, 3, 5, 2.

האם הסדר משנה את הפיזיקה? לא. כל מסלול עובר באותה גיאומטריה ובאותו חומר, ומסלולים לא רואים זה את זה. המתג "תור" מראה את אותו עץ בסדר אחר: אותם מסלולים ואותם צעדים. מה שכן משתנה עם סדר אחר הוא איזה מספר אקראי הולך לאיזה מסלול, ולכן אירוע מסוים ייראה אחרת, אבל ההתפלגות של התוצאות נשארת אותה התפלגות.

כמו ערימת תיקים על השולחן: התיק שהונח אחרון הוא הראשון שנפתח. מי שעובר על כל הערימה בסוף עובר על כל התיקים, ובאיזה סדר זה לא משנה את מה שכתוב בהם.

5

מה פעולת הצעד של ldns סופרת

הספירה החשובה ביותר של ldns היא נייטרונים שיוצאים מהממיר: הטבלה (ntuple) שנקראת leak. היא נבנית בפעולת הצעד, שרואה כל צעד של כל חלקיק ומחליטה אם לכתוב שורה.

בציור ממיר של שתי שכבות, Be ומאחוריו Pb. נייטרון נולד ב-Be, מתפזר, עובר ל-Pb, מתפזר שוב, יוצא דרך הפאה האחורית, וממשיך עד קצה העולם.

ככה זה נראה ב-src/SteppingAction.cc. התנאי של ה-if הוא כל הסיפור:

      DetectorConstruction::LayerIndex(post->GetPhysicalVolume()) < 0 &&
      fEvt->FirstLeak(track->GetTrackID()))
  {
    const G4double w = track->GetWeight();
    const G4ThreeVector& d = post->GetMomentumDirection();
    fEvt->AddLeak(w, d.z() > 0.);
    if (level >= 1) {
      const G4ThreeVector& x = post->GetPosition();
      am->FillNtupleIColumn(2, 0, evt);
      am->FillNtupleDColumn(2, 1, post->GetKineticEnergy() / MeV);
      am->FillNtupleDColumn(2, 2, d.z());
  • החלקיק הוא נייטרון.
  • הצעד נגמר על גבול גיאומטרי (fGeomBoundary), כלומר Transportation קבע אותו. פיזור באמצע השכבה לא נחשב.
  • הנפח של נקודת הסיום, שבצעד גבול הוא כבר הנפח הבא, אינו שכבה של הממיר. המעבר מ-Be ל-Pb הוא צעד גבול, אבל הנייטרון עדיין בממיר. קצת קודם באותה פונקציה יש עוד תנאי: הצעד התחיל בתוך שכבה.
  • זו היציאה הראשונה של המסלול הזה (FirstLeak), כדי שנייטרון שחוזר מהמאט ויוצא שוב לא ייספר פעמיים.

אז נכתבת שורה: מספר האירוע, האנרגיה בנקודת הסיום, ו-\(\cos\theta\), הרכיב של הכיוון לאורך ציר הקורה; בהמשך השורה גם המשקל. בריצת ה-Be נכתבו כך 6126 שורות, עם משקל ממוצע 0.219.

6

הרבה הליכים, אירועים שלמים

הריצה האמיתית לקחה 17.6 שניות על 10 הליכים (threads). ב-Geant4 יש הליך מנהל (master) שבונה את הגיאומטריה ואת טבלאות הפיזיקה פעם אחת, והליכי עבודה (workers) שמריצים אירועים. את מספר ההליכים קובע הדגל -t בשורת הפקודה של ldns, ובלעדיו כל הליבות.

בצעצוע למטה 16 אירועים על ארבעה הליכים. הליך פנוי לוקח את האירוע הבא. באירועים שבהם הפרוטון יצר נייטרון, הקצה של הבלוק ירוק.

החלוקה היא לפי אירועים שלמים: אירוע לא נחתך בין הליכים, ולכן כל המחסנית שלו, כל המשניים וכל הצעדים, חיים בהליך אחד. לכל הליך יש עותק משלו של פעולות המשתמש, ובמיוחד של הסכומים. בסוף הריצה המנהל ממזג אותם. זה הקוד מ-src/RunAction.cc, שרץ בכל הליך ובמנהל:

void RunAction::EndOfRunAction(const G4Run* run)
{
  G4AccumulableManager::Instance()->Merge();
  auto am = G4AnalysisManager::Instance();
  am->Write();
  am->CloseFile();

  if (!IsMaster()) return;

רק המנהל ממשיך ומדפיס את הסיכום. גם הטבלאות מתמזגות, לקובץ ROOT אחד. בלוג של ריצת ה-Be, אחרי שכל ההליכים סיימו, המנהל מדפיס:

Real הוא זמן השעון, 17.6 שניות. ומה עם האקראיות? כמו שראינו בפרק 1, המנהל נותן לכל אירוע זרעים משלו לפני שהוא נשלח להליך, מתוך הזרע הראשי של -s. לכן התוצאה לא תלויה במי הריץ איזה אירוע, ו--t 4 ו--t 8 עם אותו זרע נותנים אותם מספרים.

8

מעבדת האירוע

אירוע סכמטי אחד בכל פעם, מוגרל מזרע. בצעצוע חצי מהאירועים נגמרים בתגובה, כדי שיהיה מה לראות. העץ למטה נבנה בסדר שבו Geant4 מעביר את המסלולים. כמה דברים שכדאי לבדוק:

  • להגדיל את אנרגיית הפרוטון. מה קורה למספר הצעדים שלו?
  • לכבות את "משניים". כמה מהצעדים של האירוע היו של הפרוטון עצמו?
  • למצוא אירוע עם גמא ואלקטרון, ולעקוב אחרי סדר ההובלה בעץ. מי מועבר אחרי הגמא?
  • ללחוץ "שוב, אותו זרע" כמה פעמים. משהו זז?
9

אתגר: מי נקרא מתי

בכל שלב אירוע אחר, והקריאות שלו מעורבבות. צריך לסדר אותן כמו ש-Geant4 קורא להן. השמות מקוצרים: PreTracking הוא PreUserTrackingAction, ו-Stepping ×4 p הן ארבע קריאות של UserSteppingAction בצעדים של הפרוטון.

שלב בלי טעויות שווה 3 נקודות, עם טעות או שתיים 2, ואחר כך 1. הכוכבים נקבעים מסכום הנקודות, והאירועים משתנים בכל סיבוב.

כרטיס כיס

איך Geant4 בנוי, על כף היד

הקופסאות: ריצה ⊃ אירוע ⊃ מסלול ⊃ צעד. אירוע הוא חלקיק ראשוני אחד וכל הצאצאים שלו.
מסלול: track ID, parent ID (אפס לראשוני), creator process, weight שעובר בירושה.
הסדר: BeginOfRun, ולכל אירוע GeneratePrimaries, BeginOfEvent, לכל מסלול PreTracking, Stepping לכל צעד, PostTracking, ואז EndOfEvent; בסוף EndOfRun.
מחסנית: המשניים נכנסים כשההורה נגמר, והאחרון שנכנס יוצא ראשון. הסדר לא משנה את הפיזיקה.
leak של ldns: נייטרון, צעד שהתחיל בממיר ונגמר על גבול, הנפח הבא מחוץ לממיר, יציאה ראשונה.
הליכים: -t קובע כמה; כל הליך מריץ אירועים שלמים; המנהל ממזג בסוף. -s קובע את הזרע.
